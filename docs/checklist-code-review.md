
# Checklist de Code Review — Academa

## 1. Objetivo

Evaluar la calidad técnica del código de Academa,
registrar observaciones y comprobar que la versión
refactorizada conserva el comportamiento esperado.

## 2. Alcance

Archivos previstos para la revisión:

- src/inicial/Gestor.java (referencia inicial)
- src/refactorizado/ (pendiente de integración)
- src/pruebas/PruebasInicial.java
- compilar-y-probar.bat

## 3. Checklist técnico

### Clean Code
- [ ] Los nombres de clases y métodos son descriptivos.
- [ ] Los métodos tienen responsabilidades claras.
- [ ] No existe duplicación innecesaria.
- [ ] El código resulta legible y comprensible.

### SOLID y diseño
- [ ] Las clases tienen responsabilidades bien definidas.
- [ ] Existe cohesión adecuada.
- [ ] Se evita el acoplamiento innecesario.
- [ ] Las decisiones de diseño están justificadas.

### Manejo de errores
- [ ] Los errores se informan adecuadamente.
- [ ] No se ocultan excepciones relevantes.
- [ ] Las entradas inválidas se controlan correctamente.

### Pruebas y verificación
- [ ] Las operaciones principales tienen pruebas.
- [ ] Las pruebas utilizan datos aislados.
- [ ] Las pruebas se pueden repetir.
- [ ] La versión refactorizada conserva el comportamiento evaluado.

### Git y documentación
- [ ] Los commits son descriptivos.
- [ ] Los cambios se revisan antes de integrarse.
- [ ] La documentación coincide con el código existente.
- [ ] Se registran observaciones y correcciones.
